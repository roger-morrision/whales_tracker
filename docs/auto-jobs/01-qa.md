# Job 1 — QC & QA Audit

**Run date:** 2026-08-16  
**Scope:** pages, navigation, tabs/sub-tabs, buttons, links, sorting/filtering, loading/error/empty states, automated checks.  
**Method:** static flow tracing plus attempted unit, lint, build, and E2E readiness checks. No fixes were made.

## Executive result

**Release recommendation: NO-GO.** Two public routes render the wrong page, several in-app navigation controls change transient store state without changing the URL, feed filter controls are decorative, and the E2E suite contains a selector that cannot match the implementation. The installed workspace is also incomplete, so the automated suite could not execute.

## Prioritized findings

### P0 — `/whales` and `/portfolio` deep links always render Discover

- **Evidence:** both route files merely re-export the root default component (`src/app/whales/page.tsx:1`, `src/app/portfolio/page.tsx:1`). Root `Home` supplies `forcedTab="discover"` (`src/app/page.tsx:647-649`), which takes precedence over the pathname (`src/app/page.tsx:81-83`).
- **Reproduce:** navigate directly to `/whales` or `/portfolio`, refresh either URL, or open either in a new tab.
- **Actual:** Discover/Home renders while the URL indicates Whales or Portfolio. The bottom navigation derives its highlight from the URL, so content and selected navigation can disagree.
- **Expected:** each route renders its mapped view and survives refresh/deep linking.
- **Acceptance:** route-level tests assert visible Whales content at `/whales` and Portfolio/Leaderboard content at `/portfolio`, including a hard reload.

### P0 — internal tab actions desynchronize content, URL, and selected navigation

- **Evidence:** many controls call only `setActiveTab(...)` (for example Discover “Pulse” at `src/components/moby/discover-view.tsx:268-273`, wallet Portfolio at `src/components/moby/wallet-modal.tsx:358-365`, and profile quick links), while the rendered content uses store `activeTab` (`src/app/page.tsx:577-591`) but BottomNav uses `tabFromPathname(pathname)` (`src/components/moby/bottom-nav.tsx:21-26`). Only BottomNav itself also calls `router.push` (`src/components/moby/bottom-nav.tsx:39-44`).
- **Reproduce:** from `/`, press **Pulse**; alternatively open wallet profile and press **Portfolio**.
- **Actual:** view changes, URL remains unchanged, bottom navigation highlights the old page, browser Back does not reverse the transition, and refresh loses the selected view.
- **Expected:** all primary navigation is URL-driven and has consistent active state/history behavior.
- **Acceptance:** centralize tab navigation; verify URL, content, `aria-current`, Back/Forward, and reload for every entry point.

### P1 — Feeds filter chips and Reset are non-functional

- **Evidence:** `FilterChip` renders a `<button>` without an `onClick` or state (`src/components/moby/feeds-view.tsx:86-105`). “Reset filters” only pushes a toast and changes no filtering state (`src/components/moby/feeds-view.tsx:43-61`). Labels such as Transactions, Whales, Top Traders, Period, and Advanced therefore imply controls that do nothing.
- **Reproduce:** go to Feeds → Whale Watch/Movers; press each chip and Reset.
- **Actual:** no selection, list, ordering, or query changes; Reset claims success despite resetting nothing.
- **Expected:** controls open a picker or toggle an applied filter, expose selected state, update results, and Reset restores defaults.
- **Acceptance:** add behavioral tests for each chip, applied-count/state, result change, Reset, and zero-result state.

### P1 — “Refresh” does not refetch the live feed

- **Evidence:** Whales LiveFlows calls store `refreshFeeds` (`src/components/moby/whales-view.tsx:229-245`), while the network hook refetches only when its private URL/nonce changes (`src/hooks/use-gmgn.ts:32-74`). Store `refreshFeeds` only shuffles local mock flows/signals (`src/lib/moby-store.ts:1115-1125`); it cannot increment the hook nonce.
- **Reproduce:** inspect network requests, then press Live smart money feed **Refresh**.
- **Actual:** local mock state changes but `/api/gmgn/smart-money-feed` is not requested again.
- **Expected:** the visible live section invokes `useGmgn().refetch()` and accurately indicates refreshing/success/failure.
- **Acceptance:** integration test asserts a second API request and updated freshness timestamp after the button click.

### P1 — fetch failures are mislabeled as empty filter results

- **Evidence:** Discover discards the hook's `error`, then shows the same “No tokens match your filters” state whenever loading ends with an empty list (`src/components/moby/discover-view.tsx:35-47,301-305`). The API intentionally returns 503 on upstream failure (`src/app/api/solana/trending/route.ts:85-91`).
- **Reproduce:** block/fail `/api/solana/trending`, or make DexScreener unavailable.
- **Actual:** user is told filters excluded all tokens, even with default filters; there is no retry action or failure detail.
- **Expected:** mutually exclusive loading, upstream-error (Retry), genuine-empty, and filtered-empty states.
- **Acceptance:** component tests cover HTTP 503, network error, successful empty response, and filters excluding a non-empty response.

### P1 — stale-data source state can be wrong after a failed refresh

- **Evidence:** `useGmgn` reads `data` inside its effect catch (`src/hooks/use-gmgn.ts:61-67`) but excludes it from dependencies (`src/hooks/use-gmgn.ts:74`). This is a stale closure: after a successful request, a later nonce refresh can still observe the `data` value captured for that effect lifecycle and produce inconsistent source/error state.
- **Impact:** badges may show an old live source while data is stale, or switch to error inconsistently; consumers often do not render the returned `error` at all.
- **Expected:** use a ref/functional state or explicit state machine for `idle/loading/success/refreshing/stale/error`.
- **Acceptance:** fake-timer hook test: success → refresh failure preserves last data, marks it stale, exposes failure, then retry success clears it.

### P1 — E2E Whales assertion can never match current markup

- **Evidence:** E2E expects `[data-testid="trader-card"], [data-testid="trader-row"]` at `tests/e2e/app.spec.ts:115-120`; repository search finds neither attribute. Trader cards are plain clickable `<div>` elements (`src/components/moby/whales-view.tsx:92-101`).
- **Actual:** the test must time out even when traders are visible.
- **Expected:** test through accessible roles/names, or add a stable test id; clickable cards should be keyboard-accessible controls/links rather than non-focusable divs.
- **Acceptance:** E2E passes and Enter/Space can open a trader detail sheet.

### P2 — desktop search field is disconnected from modal search query

- **Evidence:** TopBar owns local `searchQuery`, but typing only updates that local state and opens the modal (`src/components/moby/top-bar.tsx:97-108`). No query value is passed to the store/modal.
- **Reproduce:** focus TopBar Search and type a token symbol.
- **Actual:** the text exists behind/alongside the opened SearchModal while modal results use their own query; clearing/closing one does not reliably clear the other.
- **Expected:** one controlled query source shared by trigger and modal, or make the top field a button that focuses the modal input.
- **Acceptance:** E2E types once and sees matching results, then Escape and clear behavior remain synchronized.

### P2 — clickable result cards lack keyboard semantics and names

- **Evidence:** TraderCard uses `onClick` on a `<div>` with no `role`, `tabIndex`, key handler, or accessible name (`src/components/moby/whales-view.tsx:92-101`). Similar card patterns should be audited globally.
- **Impact:** keyboard and switch users cannot open details; automation is forced toward brittle CSS/test-id selectors.
- **Expected:** use a semantic button/link or implement full keyboard behavior and focus indication.
- **Acceptance:** axe scan has no interactive-role violations and keyboard-only tests open/close representative token, trader, signal, and wallet details.

### P2 — navigation naming and information architecture are inconsistent

- **Evidence:** the same `whales` state is labeled **Feeds** in BottomNav, **Whales** in DesktopRail, and routes to `/feeds`; `portfolio` is labeled **Leaderboard**, rendered by `LeaderboardView`, but aliases `/portfolio`; Signals is a desktop route/rail item but absent from the four-item BottomNav (`src/lib/moby-navigation.ts:3-9`, `src/components/moby/bottom-nav.tsx:15-18`, `src/app/page.tsx:656-661`).
- **Impact:** confusing location cues, unpredictable deep links, and no direct mobile route to Signals except in-content controls.
- **Expected:** define canonical destinations and labels, redirect legacy aliases, and provide a discoverable mobile Signals entry.
- **Acceptance:** navigation matrix documents one canonical URL/label per view and all breakpoints expose equivalent destinations.
